# AI 管线说明

> 依据：`compass-kit/TECH.md`、`graphics/compass-manifest*.json`、`scripts/`。
> 一句话：**美术素材是 AI 预生成的，代码是 AI 写的，运行时一个模型都不调。**

---

## 1. 用了哪些工具

| 环节 | 工具 | 产出 |
|---|---|---|
| 编程 | Claude Code（AI 编程代理） | 整个网页：`v2/` 的应用、罗盘渲染、状态机、日记与旅程卡 |
| 生图 · 表盘 | Draw Things（本地跑 `flux_2_klein_4b_i8x`，4 步，1536×1536） | 铜罗盘盘面底图 `plate.webp` |
| 生图 · 零件 | Draw Things（本地跑 `z_image_turbo_1.0_i8x`，8 步，1024×1024） | 指针 `needle.webp`、玻璃 `glass.webp`、两道光影 `sheen-*.webp` |

| 界面与插图 | 手写 SVG / CSS（未用 AI 生图） | 表盘刻度 `dial-markings.svg`、图标、纸纹 |

## 2. 生成过程里最有用的一条经验

**模型画不准数字，就别让它画。**

表盘第一版直接让 FLUX 画「N/E/S/W + 30° 刻度」，结果 W 重复、N/S 错位，数字变成 35、20、90。改成：模型只负责材质（黄铜、搪瓷、铜绿、划痕），刻度环留白；文字和刻度由 `dial-markings.svg` 精确叠加。这是最终版能看清 330°/30° 的原因。

---

## 3. 哪些是预生成，哪些是运行时

| 项 | 时机 |
|---|---|
| 罗盘盘面、指针、玻璃、光影 | **预生成**（制作阶段出图，随仓库发布） |
| 11 张目的地铜版画 | **预生成**（文生图出 1024²，压成 160² webp，共约 90 KB） |
| 表盘刻度、界面、图标、纸纹 | **预生成**（手写 SVG / CSS） |
| 目的地、NPC 台词、阿针口头禅 | **预生成**（写在 `v2/destinations*.js`、`levels.js`） |
| 「一句话铸造」旅伴 | **运行时的本地规则**，不调模型（见下） |
| 日记成稿、旅程卡、主角卡 | **运行时本地生成**（Canvas 绘制，不调模型） |

运行时零模型调用、零外部请求：`v2/` 里没有 `fetch` 到任何 API，素材全是同目录静态文件。断网、会场 Wi-Fi 拦隧道都不影响玩。

---

## 4. 「一句话铸造」到底是什么

输入一句话 → 对这句话做哈希 → 从预设的名字 / 性格 / 口头禅词池里取出三个组合。**不调用大模型，不实时生图。**

- 好处：同一句话永远得到同一个旅伴；离线可用；现场不会因为网络抖动卡住。
- 代价：它不理解语义，只做确定性装配。这一点写清楚，不假装是实时生成。

## 5. 诚实边界

- **阿针没有独立立绘**。主角形象就是这枚 AI 生成的铜罗盘本身；主角卡里的「立绘」是它在游戏里的实际渲染。
- **目的地铜版画是 2026-10-25 当天补的**：11 张，统一「深棕暖金 + 铜版排线」，缩到 36 px 圆章里用。生成时的验收标准是「六张放一起像同一本书的插图」；第一版东门大桥和九眼桥都是多孔拱桥、认不出区别，重跑了这两张。
- **8 张 NPC 头像仍是计划**，`docs/GAME-DESIGN.md` 里列了但没做；界面靠版式、字体和手写 SVG 撑。
- 罗盘的真实感来自 AI 材质 + 精确 SVG 刻度的叠加，不是一张整图。
