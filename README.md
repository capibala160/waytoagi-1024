# 问心·指南针 · 只指方向，不指路

WaytoAGI 1024 超能 Coding 周末 · 游戏赛道

说一个地方，屏幕只给一个指南针。没有地图、没有路线、没有距离——自己找路，到了才算数。

> **产品方向：目的地优先。** 首页是「今天去哪？」，确认目的地后选「雾城模拟 / 去真实城市」，罗盘只指它。
> 会场寻宝（5 站 / 3 站）保留为游戏标签，沿线索寻宝、集章通关。
> 读 [docs/PRODUCT-TRUTH.md](docs/PRODUCT-TRUTH.md)。

**在线试玩：** https://capibala160.github.io/waytoagi-1024/
根路径自动跳到 v2 新界面 `/v2/`；旧版根应用保留在 `/legacy.html`。
电脑选「雾城模拟」，手机有罗盘选「去真实城市」；游戏模式在首页顶部的「游戏」标签。

> **当前主线：** v2 = 高清界面 + 最新玩法；根目录旧应用只做回滚。
> **真实出行口径：** 目的地坐标声明 GCJ-02（高德/腾讯），运行时转 WGS-84；精度 ≤50m、采样 ≤15s、连续 3 次，进入范围后由用户点「我到了」。

## 走法

| 走法 | 场景 | 谁用 |
|---|---|---|
| **雾城模拟** | 同一个目的地，12×12 雾城，3–6 分钟，不用出门 | 评委 / 第一次玩 |
| **去真实城市** | 真实 GPS + 罗盘，30–90 分钟 | 主产品 / 户外演示 |
| **会场寻宝 · 出门玩** | 5 站，约 5 分钟 | 游戏标签 |
| **会场寻宝 · 不出门** | 3 站，约 90 秒 | 游戏标签，评委兜底 |

## 主流程

1. 首页「今天去哪？」：输入 / 3 张目的地卡 / 换一批 / 随便走走 / 最近去过
2. 确认目的地
3. 怎么走：雾城模拟（无需出门）/ 去真实城市
4. 雾城：罗盘 + 四向移动 + 问路 NPC；抵达后出用时 / 步数 / 问路 / 迷路指数 / 星级
5. 旅伴铸造：首页「旅伴」→ 一句话生成 3 个阿针变体 → 选一个，台词和名字跟着变
6. 抵达后「写日记」：时间线 + 3 个照片位 + 一句话 → 生成 9:16 抵达证明 + 挑战链接

## 会场寻宝（5 站 / 3 站）

1. 开局说明：玩法、时长、提示灯、现场是否布置（未布置标为演示）
2. 到站确认：点「我到了」→ 固定角色问一个观察题 → 选对物件才给到达线索，选错可重试
3. 输码盖章：看纸上四位码 → 盖章 → 显示已集 X / N 枚和下一站
4. 终点拼合：最后一站把一路收集的碎片按边数（A 组）或收集顺序倒排（B 组）排好，再输最后四位码
5. 提示选择：可「自己再找找」，或「用 1 盏灯换提示」，代价写在按钮上

目的地数据在 `v2/destinations.js` / `v2/destinations-city.js`，字段：`name / blurb / lat / lon / datum / source / entrance`。现在的经纬度是成都锦江区的 GCJ-02 占位点，v2 会先转成 WGS-84 再算距离；**现场实测后更新坐标，并把 `entrance` 填成可进入的公共入口**。

## 计分

- 目标时间：出门 300 秒、不出门 90 秒、自由行/模拟 600 秒
- 每条提示折算 6 秒
- 得分 = 1000 − 250 ×（用时 + 提示×6）÷ 目标时间，保底 100
- 正常发挥约 750（老向导），快就 850+（活地图）

必须 HTTPS——手机浏览器只在安全上下文里给方向数据。

```bash
cd "/c/Users/Lenovo/Desktop/waytoagi-1024-dev"
py -3 -m http.server 8081 --bind 127.0.0.1

```

## 唯一要改的文件：`levels.js`

两套关卡都在这里：`LEVEL_SETS.outdoor`（5 站）和 `LEVEL_SETS.indoor`（3 站）。踩完点，把占位内容换成真的。

```js
{
  id: 1,
  name: '第一站',
  type: 'tutorial',          // tutorial / observe / combine / optional / final
  typeLabel: '教学',          // 线索卡上的小标签
  place: '门口右侧的绿植',     // 内部备注，玩家看不到
  code: '4821',              // 纸上写的四位码
  bearing: 30,               // 目标绝对方位：0=北 90=东 180=南 270=西
  steps: 12,                 // 建议步数，只用于提示文案
  clue: '往北偏东 30°，走十二步……',   // 出发线索：方向 + 步数 + 环境
  arriveClue: '到了墙边再看：……',      // 稳定对准后才揭示
  piece: { mark: '○', label: '0 条边' }, // 这一站的碎片
  sets: {                                 // 可选：A/B 两套谜题
    B: { code: '9153', clue: '另一套出发线索', arriveClue: '另一套到达线索' }
  },
  confirm: '方向确认，去找那面墙。',     // 稳定对准后显示
  story: '第一段记忆：……',    // 答对后盖章并解锁
  stamp: '门',               // 印章上的一个字
  freeHint: true,            // 教学站提示不耗灯
  bonus: { code: '2077', label: '加试题：……' },  // 可选
  hints: ['第一条', '第二条', '第三条']
}
```

## 游戏化

- **故事**：每站 `story` 一段，答对后盖章并解锁；结算页拼成完整故事。
- **谜题类型** `type`：教学 / 观察 / 组合 / 挑战 / 揭晓，只影响标签和提示规则。
- **提示灯**：每局 3 盏；教学站免费；解谜提示消耗一盏。
- **成就**：记忆拼图 / 独立寻路者（没用解谜提示）/ 细节观察家（答对 `bonus`）/ 同行向导（问了 3 个人）/ 活地图（≥850 分）。
- **加试题**：某站配置 `bonus`，在输码页点「加试一题」。
- **对准光环**：稳定对准 0.9 秒，罗盘外圈亮绿并显示 `confirm`。

> 方位是「上一站 → 下一站」，不要随机打乱站点顺序；要复玩，随机谜题/故事片段，或另配多套路线。

| 包 | 内容 | 入口 |

| **会场**（默认） | `destinations.js` 6 个会场目的地 + `levels.js` 5 站寻宝/A-B | 首页右上角「会场」 |
| **城市** | `destinations-city.js` 6 个城市目的地，没有固定寻宝路线 | 首页右上角切「城市」 |

- 城市包会隐藏首页顶部的「游戏」标签，只留探索模式（自由行/雾城）
- 挑战链接会自动带上 `pack=`，朋友打开就是同一个包

## 重玩与记录

- **A/B 谜题**：每站可在 `sets.B` 配第二套码和线索；开局随机 A/B，`?set=A` / `?set=B` 可指定。纸上要准备 A/B 两组码，游戏会在线索卡上标「A 组 / B 组」。
- **线索册**：行进页 HUD 的「线索册」，已完成站的线索、到达线索、故事、碎片随时可查；未到的站锁定。
- **旅程记录**：完成一局后自动存最近 5 次（localStorage）；首页「旅程记录」可重新打开结算页、旅程卡和日记。
- **首次通关**：每套路线第一次完成给「首次通关」；熟悉答案后再跑，靠「独立寻路者 / 细节观察家 / 活地图」区分，而不是只看总分。
- **到访口径**：验证码只证明解开了这一站，结算页明确标「轻量验码 · 不作为到访证明」。

**方位怎么写**：站在上一站的位置，手机平放，转到目标方向，记下读数。填进去。

**线索怎么写**：

- 一定要有方位 + 步数，否则指南针没用
- 描述要「能认出来但不直白」：别写「饮水机」，写「听见水声就到了」
- 每条线索对应一张实体纸，纸上写 4 位码

## 踩点流程（30 分钟）

1. 走一遍会场，选 5 个点：能站人、不挡路、不扰民
2. 站在 A 点，手机转到 B 点方向，记方位角
3. 数一下步数（正常步幅）
4. 每个点贴一张纸，写 4 位码
5. 把 `levels.js` 填完，自己走一遍

## 指南针体检（新手机先跑这个）

`compass-test.html` 会显示：安全上下文、数据来源、静止稳定度、采样率、原始 α/β/γ。

**通过标准**：HTTPS ✅、数据来源是「alpha（绝对）」、静止稳定度 ≤ ±5°。

**注意**：

- 微信内置浏览器会把采样率压到 1 Hz，**一定用 Chrome / 系统浏览器**
- 演示用自己那台手机，别让评委用他们的机型
- 磁吸支架、音箱、金属桌会让罗盘偏，站远一点

## 已知边界（诚实口径）

- **有的浏览器不给方向数据**：2026-10-25 实测华为浏览器（鸿蒙）只发 2 个 `deviceorientation` 事件，`alpha/beta/gamma` 全是 `null`，浏览器层面不同意外提供传感器。表现是罗盘指针不跟手；问心会在 2.5 秒后提示「没检测到罗盘：拖动表盘模拟」，**拖表盘照样能玩，GPS 和「我到了」不受影响**。换 Chrome / 系统浏览器可能恢复；用 `tools/orientation-probe.html` 30 秒可确认
- 真实 GPS 已接入，但**真机还没实走**；室内弱信号下会自动提示，不硬判到达
- 个别浏览器给的时间戳是无效值（实测华为浏览器固定返回 `10000`），v13 起不再据此判过期；排查用 `tools/gps-probe.html`
- 目的地仍是成都锦江区 GCJ-02 占位点，`entrance` 全部「入口待实测」；现场实测后更新坐标和入口
- 防作弊靠人：玩家可以偷偷用导航，游戏不做裁判
- 采样率低（1 Hz）时，走路读数会滞后；最好站定再读
- 会场 Wi-Fi 可能拦隧道，备手机热点
- 真实出行在室内基本不可用；评委/室内用雾城模拟
- 旧根应用 `/legacy.html` 不再维护，不要拿它验收定位
