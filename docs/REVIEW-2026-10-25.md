# 代码审阅与优化清单 · 2026-10-25

> 来源：提交当天对 v2 主应用的静态代码审阅（未做真机实测）。

## 1. 审阅结论（原文照录）

优先优化「第一次出发 → 可靠抵达 → 愿意分享」这条链路。

| 优先级 | 优化点 | 建议 |
|---|---|---|
| P0 | 真实出行的可靠性 | 在 iPhone / Android 上验证拒绝权限、弱信号、锁屏恢复、接近入口四种场景；验收重点是**指针恢复、状态提示、「我到了」按钮**是否一致 |
| P0 | 目的地入口准确性 | 先精选几个实测地点，补齐入口坐标、入口照片、开放时段、入口描述；先把少量地点做可靠，再扩充数量 |
| P1 | 首次模拟更直接 | 当前模拟仍是雾城网格 + 方向键，目标是真转手机 + 一个「前进」按钮；优先补约 60 秒的旅程模拟 |
| P1 | 搜索与目的地卡更可信 | 增加别名搜索、回车确认；目的地卡补照片、推荐理由、适合时段；未确认位置前不要写「附近」，改「精选去处」 |
| P1 | 分享能带回朋友 | 抵达图的链接换成可扫描二维码，验证扫码能直接打开对应目的地；旅程用「和我去同一个地方」，游戏用挑战文案 |
| P2 | 照片与日记保存 | 照片从 localStorage 改 IndexedDB Blob，加压缩、失败提示、删除入口；日记从实际照片、问路和用户记录生成 |

工程侧两条：

- **拆分主文件**：`v2/game.js` 约 4,400 行，同时管传感器、定位、存档、游戏、海报。建议先抽定位与存储，再分离旅程与游戏状态。
- **统一文档入口**：README / 产品真值 / 状态看板明确「已实现／待实现」，别让后来的开发改到旧版本（审阅时发现 `docs/PRODUCT-TRUTH.md` 标题仍是旧名「一根筋」，`v2/game.js` 头注释仍是「会场微定向」）。
