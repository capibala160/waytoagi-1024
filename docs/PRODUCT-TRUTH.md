# 产品真值 · 一根筋

> 这是产品的宪法。和它冲突的功能，一律不做。
> 最后更新：2026-10-24 · v0.2（旅程 / 游戏分开；目的地卡；静态大罗盘；照片日记；二维码分享）

---

## 一句话

**你说一个地方，App 只指方向，你自己走过去。**

---

## 是什么

1. 用户**输入或选择一个真实目的地**。不是系统派的关卡，不是固定的 5 站。
2. 顶层只有两种模式：**旅程**（自己选地方，不记分）和**游戏**（接受挑战，有分数）。
3. App 只做一件事：**罗盘指向那个地方**。盘面固定，只有指针转。
4. **没有地图、没有路线、没有 turn-by-turn、没有距离数字。**
5. 用户靠三样东西到达：自己的方向感、街上的地标、问路人。
6. App 记录：用时、问了几个人、绕了多少路、路上的照片和一句话。
7. 到达后：旅程模式生成**旅程小结** + **日记**（从真实片段长出来）+ 一张带二维码的**旅程小结图**；游戏模式生成**得分卡**（速度分 + 相遇分）。
8. 然后：**换一个目的地，再来一次。**

---

## 不是什么

- **不是寻宝游戏。** 主产品没有线索、没有 4 位码、没有固定 5 站、没有”通关”。会场寻宝是活动模式，不是主产品。
- **不是导航。** 不告诉你怎么走。
- **不是地图。** 过程中没有地图；到达后才把你走过的路画出来。
- **不是打卡清单。** 旅程模式的目的地是用户选的，不是系统派的。
- **不是所有模式都记分。** 旅程模式没有分数、星级、排名；只有游戏模式有。
- **不是闯关。** 旅程模式没有第 1 关、第 2 关；只有"我想去这里"。

---

## 中心

```
第一屏：旅程 / 游戏

旅程：
今天去哪？[搜已收录地点 / 建议 / 随机]
   ↓
选中目的地：底部卡（照片 + 3 条理由 + 适合时段 + 公共场所；未获取位置前不承诺步行可达）
   ↓
怎么走？[模拟 · 无需出门 / 去真实城市]
   ↓
转手机 + 按“前进” / 真实城市走路
   ↓
罗盘只指它（盘面固定，只转指针）
   ↓
走、问人、拍照片、记一句
   ↓
到了 → 旅程小结（不评分）→ 日记（有片段才写）
   ↓
旅程小结图 + 二维码 → 分享
   ↓
换一个目的地

游戏：
游戏 → 选挑战 → 棋盘走 → 问人 / 事件
   ↓
到了 → 速度分 + 相遇分 + 星级 → 挑战朋友
```

**旅程里顺序不能反：目的地第一，走法第二，罗盘第三。**
**顶层先选旅程 / 游戏**：不要让旅程页出现关卡，也不要让游戏页变成目的地搜索。

---

## 两种模式的分界

| | 旅程模式 | 游戏模式 |
|---|---|---|
| 用户想要 | 去一个地方，走一段路 | 挑战一局，看看得多少分 |
| 目的地 | 自己搜 / 选 | 系统给 |
| 操作 | 转手机 + "前进"；真实城市走路 | 棋盘方向键 / 滑动 / 键盘 |
| 分数 | 没有 | 速度分 + 相遇分 |
| 结果 | 旅程小结：走了多久 / 遇见谁 / 留下什么 | 得分卡：两条分 + 总分 + 星级 |
| 分享 | 旅程小结图 + 二维码 | 挑战卡 + 挑战链接 |
| 日记 | 主产品的一部分 | 可选 |

**一条红线：旅程模式不出现分数、星级、排名；游戏模式必须同时出现两条分。**

---

## 为什么上一版偏了

- 黑客松要“评委在桌前能玩一局”，我们做了一个 5 关寻宝：线索、4 位码、结算。它可玩，但中心是“通关”，不是“去我想去的地方”。
- 设计稿也跟着偏：雾城网格、3 张目的地卡、关卡、输码。目的地变成了菜单，不是输入。
- 结果：用户没有“输入目的地”的动作；产品变成了一个城市定向越野。

**5 关寻宝可以保留为“路线模式 / 活动模式”，但它不是主产品。**

---

## 技术上怎么“输入目的地”

一个地点要有经纬度，罗盘才知道往哪指；还要有照片和理由，用户才知道为什么去。

| 做法 | 成本 | 适合 |
|---|---|---|
| 策展列表：6-10 个成都地点，带经纬度、照片、3 条理由、别名；输入框本地过滤 | 最低，不用 API，离线可用 | 黑客松、首发城市 |
| 地图 POI 搜索：高德/腾讯，把地名变成经纬度 | 中，需要 key、网络、合规 | 正式产品 |
| 朋友发链接：链接里带目的地 ID，扫码打开同一地点 | 低 | 挑战/分享 |

罗盘数学不变：

```
当前位置（经纬度） + 目的地（经纬度）
  → 方位角
  → 指针角度 = 方位角 − 手机朝向
```

**模拟**：同一个目的地，把当前位置虚拟到目的地附近；用户真的转动手机，按“前进”沿手机朝向走约 18 米。不是网格，不是方向键，不是另一个游戏。

**罗盘表现**：盘面固定不动，只有指针转；罗盘占行进页主视觉，390 宽屏表盘 ≥ 330px。

## 体验的七个瞬间

1. **输入**：用户说“我想去望平街”。这是用户自己的选择；搜索只搜已收录地点，不假装能搜全城。
2. **确认**：屏幕下半部一张卡：照片、3 条具体理由、适合时段、入口状态、公共场所。不显示精确距离，也不提前承诺步行可达。
3. **出发**：罗盘扫入，盘面固定，指针找到方向。阿针说“往那边”。
4. **迷路**：没有地图，只有街名、地标、指针。用户开始读城市。
5. **问路**：点“我问了个人”，计数 +1，看到一句“多了一个人帮你记着”。有人指对，有人指错。
6. **抵达**：系统筛掉过期/低质量/漂移的定位，进入范围后由用户点「我到了」；阿针说“到了。我早说过。”
7. **复述**：旅程小结（走了多久 / 遇见谁 / 留下什么）+ 日记（有照片或一句话才写）+ 带二维码的旅程小结图。用户把它发出去；朋友扫码走同一个地方。

---

## 只指方向的硬边界

- **旅程模式不出现**：距离、步数、预计时间、路线、转向指令、地图。
- **数字只在校准页和游戏层出现**：Heading/Target 数字只用于罗盘校准；寻宝的方位/步数/4 位码属于游戏模式，不进入旅程。
- **盘面固定，只转指针**：指针角度 = 目标方位 − 手机朝向；对准时指针朝上。顶部是手机前方参考，不再声称是真实北。
- **到达由用户确认**：系统只筛掉过期、低质量、漂移的定位；进入范围后由用户点「我到了」。

## 设计检查清单

任何新功能，先问：

- [ ] 它是否让“输入目的地”更清楚？
- [ ] 它是否让“只指方向、不指路”更纯粹？
- [ ] 它是否让“问人”更自然？
- [ ] 它是否让用户留下真实片段（照片、一句话）？
- [ ] 它是否让“到达后的故事”更好分享，且能带回一个朋友？
- [ ] 它是否让旅程和游戏的区别更清楚，而不是把两者混在一起？
- [ ] 它是否让罗盘更像主角（盘面固定、指针转、占据屏幕）？
- [ ] 它是否把产品推回“寻宝/闯关/导航”？

前七条是加分，最后一条是红线。

## 当前仓库的现实

- 线上根路径已经是**目的地优先原型**：首页「旅程 / 游戏」标签，搜/选地点 → 确认 → 模拟或真实城市 → 罗盘 → 到达 → 结果。
- 模拟已经用手机朝向 + “前进”移动；真实城市已经接 Geolocation（浏览器定位）和 DeviceOrientation（手机朝向），仍需真机复测。
- 雾城 12×12 网格和方向键属于**游戏模式 / 旧版演练**，不是旅程模拟。
- 会场寻宝（5 站 / 3 站）保留为**活动模式**，不是主入口。
- v0.2 的 11 项需求（R1-R11）只写进文档，代码按 `docs/STATUS.md` 排期；不要拿文档当成已实现。
- `smooth/` 是 2026-10-24 的冻结备份，不再维护；所有修改只进根目录。
