### 4.4 Mike 离线协议

Mike 可能在黑客松中途离线几小时。原则：**不等，不空转，不把决定留到回来。**

**离线前 30 分钟**，Mike 在 `docs/DECISIONS.md` 留一张交接卡：

- 当前做到哪。
- 下一步是什么。
- 未决问题 + 默认答案。
- 谁备份哪一块。

**离线期间**：

- 产品/文案：C 拍板。技术：B 拍板。视觉：C 拍板。跨域：B 和 C 商量，30 分钟内定。

- 视频：B 主剪；Mike 不在就用字幕旁白，不等真人配音。
- Mike 的手机壳、铸造、日记、分享界面：C 接 UI，B 接数据，不等待。

**Mike 回来后**：

- 只做验收、补文案、最终确认，不推翻已经能用的东西。
- 要改，先问"这个改动会不会让 16:00 交不上？"会，就不改。

## 5. 协作方式

### 5.1 工具

| 用途 | 工具 |
|---|---|
| 代码 | GitHub 仓库，`main` 始终可部署 |
| 沟通 | 一个群，不开第二个 |
| 文档 | `docs/`，单一事实来源 |
| 设计 | `designs/`，HTML 稿 |
| 任务 | GitHub Issues 或一张共享看板，不超过 15 个卡片 |
| 部署 | Vercel，每次 push 自动预览 |

### 5.2 Git

- `main`：始终可部署。
- `feat/xxx`、`fix/xxx`：短分支，半天内合并。
- 提交信息：
  ```
  feat: 添加雾城网格与移动
  fix: 修复罗盘在 0 度跳变
  content: 补 6 张目的地卡
  ```
- 不提交：`node_modules`、密钥、大图源文件（放 `assets/source/` 并 gitignore）。
- 三个人都可以改代码，但**不跨模块改别人的核心文件**：要改先在群里说一声。
- 合并前至少一个人看一眼；28 小时不搞正式 review。

### 5.3 文档

- 所有决策写进 `docs/`，群里说的不算。
- 每次砍功能，更新 `HACKATHON.md` 的砍清单。
- 文案改动，更新 `COPY.md`。
- 数值改动，只改 `constants.js`，并同步 `GAME-DESIGN.md`。
