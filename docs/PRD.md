## 1. 定位

### 1.1 这是什么

**犟针**是一款手机网页应用，把"导航"反过来做。

普通导航软件告诉你：往前 200 米右转，再走 3 个路口。它把城市压缩成一条蓝色路线，你不需要看街，不需要记路，也不需要和任何人说话。

犟针只做一件事：**告诉你目的地在哪个方向，然后闭嘴。**

- 没有地图
- 没有路线
- 没有"前方 200 米右转"
- 没有距离数字（默认）
- 只有一个指针，和一座需要你自己读懂的城市

你要到目的地，只能靠三样东西：自己的方向感、街上的招牌和地标、以及问路人。

抵达之后，App 会把你实际走过的路线画出来，配上一张"旅程小结图"；如果你留下照片或一句话，再长成一篇冒险日记。你可以把它发给朋友，也可以让朋友走同一条路。

### 1.2 为什么做

导航软件优化的是"确定性"：用最少的思考、最短的时间，把你送到。它很高效，但它也把城市变成了传送带。

犟针优化的是"体验"：目的地是确定的，路线是不确定的。它把一次普通出门变成一个小冒险，把"问路"这件有点尴尬的小事变成游戏里的一枚勋章，把"到达"变成一张可以炫耀的证书。

《纽约客》写的那枚只指向时代广场 Olive Garden 的罗盘，5000 人排队订购。它不是一个更好的导航工具，它是一个**故事发生器**。人们买的不是方向，是"我今天有一段可以讲的事"。

### 1.3 产品的一句话

> **目的地是确定的，路线不是。**

v0.2 起，产品有两个顶层入口：

- **旅程**：自己选一个地方，罗盘只指方向。不记分、不排名，只留下经历。
- **游戏**：接受一局挑战，有目标、有分数。分数来自两条线：速度 + 相遇。

两者共用同一枚罗盘、同一个目的地数据、同一套问路和日记组件。区别在目标、结果和分享，不在罗盘。

| 项 | 内容 |

| 产品名 | **犟针**（jiàng zhēn） |
| 英文名 | Stubborn Needle |
| 标语 | **只指方向，不指路。** |
| 主角 | **阿针**，一枚只认一个方向的铜罗盘 |
| 主角一句话 | 一枚嘴硬心软的铜罗盘，只指方向，不给路线，你绕路它会叹气 |

## 2. 用户

### 2.1 核心人群

| 人群 | 画像 | 他们想要什么 | 犟针给什么 |
|---|---|---|---|
| **周末搭子** | 24-33 岁，一二线城市，citywalk 常客，2-4 人小团体 | 一个不用动脑、又不落俗套的周末计划 | 一张目的地卡，一段 1-2 小时的共同冒险 |
| **城市游客** | 25-40 岁，到陌生城市出差或旅行 | 真正认识一座城，而不是打卡 | 用身体记住街道，而不是跟着导航走 |
| **约会中的两个人** | 20-35 岁，想找低成本的共同活动 | 有话可聊，有事可做 | 罗盘制造话题，问路制造共同记忆 |
| **独行者 / 社恐** | 20-35 岁，想出门但不想社交 | 一个安全的出门理由 | 问路按钮把社交变成游戏动作，可做可不做 |
| **社群组织者** | 25-40 岁，组织 10-50 人的城市活动 | 一套现成的城市游戏，有排行榜、有海报 | 活动包：同一目的地、不同起点、统一榜单 |

### 2.2 非目标用户

- 赶时间的人：上班通勤、赶飞机、找医院。这类场景请用高德/百度地图。
- 不愿意走路的人：犟针的乐趣来自步行和观察。
- 需要无障碍导航的视障用户：犟针不是无障碍导航工具，虽然会做基础适配，但不替代专业产品。

### 2.3 用户任务（JTBD，Jobs to be Done，用户想完成的事）

1. **"周末不想再去商场，但也不想做攻略。"**
   → 给我一个具体、有点意思的目的地，别让我选。
2. **"我在这个城市住了五年，但其实只认识公司和家。"**
   → 让我用游客的眼睛重新走一遍。
3. **"我想和这个人多待一会儿，但不知道聊什么。"**
   → 给我们一个共同任务，让对话自然发生。
4. **"我想做点能发出去的东西，但不想摆拍。"**
   → 给我一张有信息量的旅程小结图，配一段真的故事。
5. **"我想验证我到底认不认路。"**
   → 给我一个可以重复挑战、有星级和时间的关卡。

## 3. 洞察

### 3.1 从《纽约客》那枚罗盘学到的五件事

1. **约束制造故事。** 一个只能指一个方向的罗盘，比一个什么都能查的手机更好玩，因为它把"找路"变回了问题。
2. **目的地要具体、要有点荒诞。** "时代广场的 Olive Garden"比"附近任意餐厅"好笑得多，也值得走。目的地本身要有故事。
3. **问路是高潮。** 两个人在斯塔滕岛海边，罗盘指向水，他们只能去问长椅上的一对夫妇。那段对话是整篇文章最好的部分。
4. **到达不是终点，复述才是。** 他们走进餐厅，对领位员说"我们跟着罗盘来的"，这才是产品的完成时刻。
5. **法律是产品的一部分。** Olive Garden 的律师函说明：用别人的品牌做目的地，必须先拿授权。这也反过来证明，品牌愿意为"有人专门走过来"付钱。

### 3.2 中国市场信号

| 信号 | 数据 | 对我们的意义 |
|---|---|---|
| citywalk | 小红书话题浏览 21 亿次，搜索同比增长 140 倍，相关笔记 370 万篇；24-33 岁为主力 | 城市漫步已经是大众行为，不需要教育市场 |
| 搭子文化 | 小红书"搭子"内容推动猫鼠游戏第二轮爆发 | 小团体、低门槛、可组队是刚需 |
| 猫鼠游戏 | 单场常达数十至上百人，收费 9.9-29.9 元，小红书相关笔记 26 万篇 | 位置类线下游戏有真实付费意愿，但依赖地图共享 |
| Randonautica | 2020 年夏天约 1080 万用户；随机坐标导致大量"垃圾桶级"目的地 | 纯随机不行，目的地必须被策展 |
| Jet Lag: The Game | 19 季，靠挑战卡、规则变体和重玩性撑住 | 游戏化结构比重内容更耐玩 |
| Polarsteps | 自动记录路线、生成旅行日记、可分享，4.7 分约 37 万评价 | 日记和分享是成熟需求，但它是"记录"，不是"游戏" |

### 3.3 市场空位

现有产品各自只占一角：

- **Locator**：机制最接近，但只是一个网页小玩具，没有游戏循环、没有日记、没有中文内容。
- **As The Crow Flies**：极简罗盘导航，是工具，不是游戏。
- **nomap**：为视障用户做的方向指引，强调震动和箭头，不是冒险。
- **Randonautica**：随机目的地，有病毒传播，但目的地的质量不可控，且出过安全事故。
- **Polarsteps**：旅行日记和分享做得很好，但它是事后记录，不是过程游戏。
- **猫鼠游戏 / 高德群组**：位置社交游戏，规模大，但核心是"追逃"，依赖实时地图。
- **小红书 citywalk 内容**：有路线、有笔记，但没有工具，也没有"只给方向"的约束。

**没有人把"盲罗盘 + 真实城市 + 游戏循环 + 冒险日记 + 社交分享"合在一起。** 这就是犟针的位置。

## 4. 目标

### 4.1 产品目标（v1.0，上线后 3 个月）

| 指标 | 目标 | 说明 |
|---|---|---|
| 开局 → 抵达（真实城市） | ≥ 60% | 开始走的人里，六成能走到 |
| 首次模拟 → 75 秒内抵达 | ≥ 80% | 第一次就要摸到核心乐趣 |
| 抵达 → 留下片段 | ≥ 50% | 照片或一句话，让日记有根 |
| 旅程小结图 → 扫码打开 | ≥ 15% | 分享要带回新朋友 |
| 7 日内二次开局 | ≥ 25% | 证明"想再走一次 / 想再玩一局" |
| 平均单次用时（旅程） | 25-90 分钟 | 太短没故事，太长劝退；**不做排名** |
| 平均单次用时（游戏） | 3-6 分钟 | 一局完整挑战 |
| 目的地好评率 | ≥ 80% | 解决"垃圾桶问题" |
| 安全事故 | 0 | 不可妥协 |

### 4.2 北极星指标

> **每周完成的冒险数** = 抵达目的地并生成旅程卡或日记的次数。

不是安装量，不是日活。因为犟针的价值不在"打开"，在"走完并留下故事"。

## 5. 原则

这六条是产品决策的宪法。功能可以砍，原则不能破。

1. **方向确定，路线不确定。**
   罗盘只回答"在哪边"，不回答"怎么走"。
2. **地图是走出来的，不是给出来的。**
   出发时没有地图。走过后，你走过的路才会变成地图。
3. **绕路是内容，不是错误。**
   不惩罚迷路，不催促进度。迷路指数是一个可以炫耀的标签。
4. **人是最好的导航。**
   问路不是备用方案，是核心玩法。每一次问路都值得被记录。
5. **到达不是终点，故事才是。**
   结果页的第一优先级不是分数，是"这段路能不能被讲出来"。
6. **安全高于惊喜。**
   任何可能让人走进危险、私人区域或夜路的设计，一律砍掉。

### 5.1 七幕

产品的体验由七个瞬间组成。每个瞬间都要被设计，不能靠运气。

| 幕 | 时刻 | 用户感受 | 设计动作 |
|---|---|---|---|
| 1 | 第一眼（0-10 秒） | "这东西有点意思" | 罗盘指针扫入，阿针睁眼，说"往那边。" |
| 2 | 出门（10-40 秒） | "这个目的地有点怪，我想去" | 屏幕下半部弹出目的地卡：照片 + 3 条具体理由 + 适合时段；仍不给距离、不给地图 |
| 3 | 第一次迷路（3-8 分钟） | "我是不是走错了" | 迷雾、建筑挡路、阿针叹气，但不弹"你走错了" |
| 4 | 第一次问路（5-15 分钟） | "原来还能问人" | 一个具体的人、一段具体的话；点按钮后有一句轻反馈和计数 |
| 5 | 抵达（20-60 分钟） | "到了" | 指针旋转、减速、咔哒锁定；阿针说"到了。我早说过。" |
| 6 | 揭晓（到达后 1 分钟） | "原来我走了这么一条路" | 把你走过的路画成一条线，给形状起个名字 |
| 7 | 复述（到达后 5 分钟） | "这个可以发" | 旅程小结图 + 二维码 + 日记（如果留下了照片或一句话） |

七幕里最重要的是第 4 幕和第 5 幕。第 4 幕是人的连接，第 5 幕是奖励。如果只能做好两幕，做这两幕。

### 5.2 反体验

- 不显示距离数字。
- 不弹"你走错了"。
- 不惩罚绕路。
- 不强制注册。
- 不让 AI 替用户抒情。
- 不在抵达前给地图。
- 不把问路做成"失败后的提示"。
- 不用签到、积分、连续登录制造压力。
- 不在旅程模式显示分数、星级、排名。
- 不旋转整个罗盘盘面；只让指针转。
- 不用模板编造用户没做过的事。

### 5.3 反目标（即使做出来了也算失败）

- 变成一个"套了罗盘皮肤的地图 App"。
- 用户为了抄近路穿过马路、工地、私人小区。
- 目的地无聊到让人想说"就这？"。
- 日记是千篇一律的 AI 废话，用户不想发。
- 第一局好玩，第二局一样。
- 为了留存，加入签到、积分、强制社交。
- 旅程和游戏混在一起：旅程页出现分数，游戏页变成目的地搜索。
- 罗盘缩成一个小角标，用户看不清指针。
- 分享图没有邀请，朋友点开不知道要做什么。

## 6. 范围

### 6.1 MVP 范围（P0）

> 这是产品 MVP 的完整范围，不等于黑客松 24 小时必须全做完。
> 黑客松实际承诺哪些，见 6.1.1 的「建议阶段」；别把整张表当成 10 月 25 日的任务单。

| 模块 | 内容 | 为什么必须在 |
|---|---|---|
| 开场 | 品牌页、一句话说明、开始按钮 | 一看就会玩 |
| 旅伴铸造 | 一句话生成阿针变体（姓名、性格、立绘） | 赛道要求"一句话变出主角" |
| 模式选择 | 顶层「旅程」（默认）/「游戏」；模拟和真实是走法，不是模式 | 两种目标不能混 |
| 目的地卡 | 首页 3 张池子 + 选中后底部详情卡（照片 + 3 条理由 + 适合时段/入口状态） | 目的地质量决定体验 |
| 搜索 | 只搜已收录地点；别名、回车、无结果提示 | 不能让用户以为能搜任意地点 |
| 模拟走法 | 转手机 + 一个"前进"按钮；首次 60 秒内抵达 | 评委和新用户先体验核心 |
| 罗盘 | 指针指向目的地，不显示距离，靠近时加速抖动 | 产品的灵魂 |
| 问路 | 点击 NPC 得到指路；"我问了个人"有轻反馈和计数 | 核心玩法 |
| 计时 | 正计时，记录用时、步数、问路次数 | 用户明确要求 |
| 结果 | 旅程小结（无分数）/ 游戏得分卡（速度分 + 相遇分） | 两种模式的结果必须不同 |
| 日记 | 从照片或一句话长出来；最多 9 张照片；没有片段只出旅程卡 | 用户明确要求 |
| 分享 | 旅程小结图 + 二维码；游戏挑战卡 + 挑战链接 | 传播闭环 |
| 重开 | 换目的地、换起点、保留旅伴 | "想再玩一局" |
| 视觉 | 中文界面、深色默认、明暗切换、390×844 与 430×932 | 项目硬规则 |
| 无障碍 | 44×44 点击区、16px 正文、13px 最小可点字号 | 项目硬规则 |

### 6.2 P0.5（有余力才做）

- 真实城市：真实 GPS + 手机罗盘 + 6 个会场附近的目的地（代码已接入，黑客松只做视频演示）。
- 事件卡：路上随机遇到 4 个小事件（猫挡路、突然下雨、街头艺人、修路）。
- 道具卡：问路券、旧纸条、半瓶水。
- 实时 AI 铸造与日记（需要服务端代理，避免前端暴露密钥）。

### 6.3 P1（黑客松之后，v1.0）

- 目的地搜索：接入高德/腾讯地图 POI（兴趣点，地图上的地点数据）。
- 盲盒目的地：按半径、类别、营业时间随机。
- 账号与云同步：日记跨设备。
- 应用内广场：真实用户的抵达卡信息流。
- 挑战链接、排行榜、每周盲盒。
- 安全功能：实时位置共享、紧急联系人、夜间提醒、禁区过滤。
- PWA 安装（把网页加到手机桌面，像 App 一样打开）。

### 6.4 P2（更远）

- 原生 App：后台罗盘、震动反馈、锁屏小组件、手表。
- 组队模式：同一目的地、不同起点、团队榜单。
- 城市包：与文旅局、商圈、独立店主合作。
- 品牌目的地：品牌付费成为目的地，但必须明确标注，且不得干预罗盘。
- 线下活动包：团建、社群、婚礼、毕业旅行。

### 6.5 明确不做

- 不做 turn-by-turn 导航。
- 不做实时地图。
- 不做距离数字（至少默认不做）。
- 不做社交 feed 的算法推荐（v1 只做时间线）。
- 不做用户生成目的地的公开市场（先解决审核和安全）。
- 不做广告变现（先做品牌目的地和活动包）。

## 7. 功能

### 7.1 首页

**目标**：3 秒内让人知道这是什么，并开始。

结构从上到下：

1. 品牌区：犟针 logo + "只指方向，不指路。"
2. **顶层模式标签**：「旅程」（默认）/「游戏」。
3. 旅程首屏：
   - 标题："今天去哪？"
   - 搜索框："搜搜已收录的成都地点，比如：望平街"。
   - 3 张目的地卡 + "换一批"。
   - "随便走走"。
   - 最近去过。
4. 游戏首屏：挑战列表（雾城 / 会场活动），不是目的地搜索。
5. 我的冒险：最近 3 篇日记 / 旅程记录。
6. 底部：安全说明、关于、明暗切换。

**MVP 的"少即是多"**：不做底部 Tab，不做个人主页，不做关注。首页就是"选一个地方 + 看自己的日记 + 想挑战时进游戏"。

### 7.2 旅伴铸造

**目标**：用一句话让主角出现，并让用户觉得"这是我造的"。

流程：

1. 输入一句话，最多 30 字。
2. 三个示例芯片：
   - "一个嘴硬心软的铜罗盘"
   - "见过世面的老怀表"
   - "刚出厂、方向感天才"
3. 点击"铸造"。
4. 1.2 秒装配动画：黄铜零件、齿轮、指针依次落位。
5. 出现角色卡：名字、一句话性格、3 个特质、立绘、口头禅。
6. 操作："换一个" / "就它了"。

**技术兜底**：如果没有可用的 AI 接口，用关键词映射到 6 个预设角色（仍然是 AI 生成的形象），保证 1.2 秒内出结果。有接口时，用服务端代理调用大模型（LLM，能理解和生成文字的大模型），3 秒超时后回退到预设。

**角色卡**要能单独导出为图片，作为黑客松的"主角卡"提交物。

### 7.3 模式：旅程 / 游戏

顶层只分两种模式。**模拟和真实是"走法"，不是模式。** 这条规则解决现在"探索 / 游戏 / 演练 / 实战"四个词混在一起的问题。

| | 旅程模式（默认） | 游戏模式 |
|---|---|---|
| 用户问题 | "我想去这个地方" | "我想挑战一局" |
| 目的地 | 用户搜索或选择 | 系统给关卡或挑战目的地 |
| 计时 | 记录，但不评分 | 计时，进分数 |
| 分数 | **没有**分数、星级、排名 | **两条得分线**：速度分 + 相遇分 |
| 结果页 | 旅程小结：走了多久、遇见谁、留下什么 | 得分卡：速度分、相遇分、总分、星级 |
| 日记 | 主产品的一部分 | 可选，不影响分数 |
| 分享 | 旅程小结图 + 二维码 | 挑战卡 + 挑战链接 |
| 入口 | 首页「旅程」标签，默认 | 首页「游戏」标签 |
| 视觉 | 暖色、纸张、手账 | 黄铜、刻度、挑战 |

**硬规则**：

1. 旅程模式的结果页不出现分数、星级、排行榜、用时排名。
2. 游戏模式的结果页必须同时出现速度分和相遇分，不能只给总分。
3. 两种模式共用罗盘、目的地数据、问路、照片和日记组件；区别在目标、结果和分享。
4. 会场寻宝是"活动模式"，放在游戏模式下面，不叫主游戏。
5. 模式名只用在顶层：旅程 / 游戏。不要在页面里混用"探索""演练""实战"作为模式名；模拟 / 真实只描述走法。

### 7.4 目的地卡与搜索

#### 7.4.1 选中后的详情卡（R1）

用户在首页点一张目的地卡或一条搜索结果后，**屏幕下半部（约 45% 高）滑出详情卡**。上半部仍能看到罗盘或首页背景。

卡片内容，从上到下：

1. **照片**：横图 16:9，展示目的地本身，不是通用风景图。
2. **名字** + 一句短描述。
3. **3 条"值得去"的理由**：必须是具体的探索目标，不能写"很热闹""很出片"这种空话。
4. **适合时段**：白天 / 傍晚 / 晚上。
5. **入口状态**：开放 / 需预约 / 只在白天开。没有数据就写"入口情况未知"，不编。
6. **主按钮"出发"**，次按钮"换一个"。
7. 下滑或点空白处收起。

仍然不显示：距离数字、地图、路线、预计步行分钟数。

**理由的写法**：

| 不要写 | 要写 |
|---|---|
| 晚上最热闹 | 找桥头那家只在晚上出摊的冰粉 |
| 咖啡馆挨着茶馆 | 看咖啡馆和茶馆隔着一棵树做生意 |
| 适合散步 | 去河边找一张能坐着看落日的长椅 |

**示例（上线前实地核实）**：

| 目的地 | 理由 1 | 理由 2 | 理由 3 | 适合 |
|---|---|---|---|---|
| 望平街 | 去河边找一张能坐着看落日的长椅 | 找一家门口有竹椅的茶馆，点一碗盖碗茶 | 看咖啡馆和茶馆隔着一棵树做生意 | 傍晚 |
| 人民公园 | 找到鹤鸣茶社最老的那排竹椅 | 看一次掏耳朵，听一次响钳 | 在湖边找一张没人下棋的石桌 | 白天 |
| 九眼桥 | 数清桥上有几个桥洞 | 找桥头那家只在晚上出摊的冰粉 | 看河面把灯光拉成一条线 | 晚上 |

**照片规则**：

- 必须是真实目的地的照片；自己拍或拿到授权，不用无关素材图。
- 照片要能认出来：门头、招牌、长椅、桥洞，不拍抽象纹理。
- 每张照片记录拍摄日期；超过 12 个月换一次。
- 照片压缩到最长边 1280px、JPEG 0.7，单张 < 300KB。
- 没有照片的目的地不上线；不能用 AI 生成一张"看起来像"的图冒充实地。

**数据字段**：

```js
{
  id: "wangping",
  name: "望平街",
  aliases: ["望平街", "河边", "香香巷"],
  photo: "assets/dest/wangping.webp",
  reasons: [
    "去河边找一张能坐着看落日的长椅",
    "找一家门口有竹椅的茶馆，点一碗盖碗茶",
    "看咖啡馆和茶馆隔着一棵树做生意"
  ],
  bestTime: "傍晚",          // 白天 | 傍晚 | 晚上
  access: "河边步道全天开放",
  blurb: "河边一条街，咖啡馆挨着茶馆"
}
```

#### 7.4.2 搜索（R2）

**现在的承诺要收窄。** 首页写"输入一个地方"，用户会以为能搜任意地点；实际只过滤内置列表。v0.2 起改成明确口径：

- 输入框 placeholder：**"搜搜已收录的成都地点，比如：望平街"**。
- 输入框下方或右侧写：**"已收录 12 个成都地点"**（数字随数据变）。
- 搜索范围：名字、别名、一句话描述、理由关键词。不搜街道地址，不搜任意 POI。
- **回车触发搜索**；"搜"按钮同样触发。
- 输入框有内容时显示"清除"按钮。
- 结果最多 6 条，每条显示名字 + 一句理由，不显示距离。
- 无结果：**"还没收录「XXX」。先试试：望平街 / 人民公园 / 九眼桥"**，下面给 3 个可点芯片。
- 不做"猜你想去"的假智能；不做地图选点。
- 正式开放任意地点搜索（接 POI，地图上的地点数据）后，才把文案改回"输入一个地方"。

**别名规则**：每个目的地至少 1 个别名；用用户会说的词，不用官方全称。例如"太古里"的别名可以有"远洋太古里""太古"，"人民公园"的别名可以有"公园""鹤鸣茶社"。

**验收**：

- 输入"太古"能找到太古里。
- 输入"远洋"能通过别名找到太古里。
- 按回车能出结果，不用非得点按钮。
- 无结果时，用户能在 1 次点击内选一个推荐地点。

#### 7.4.3 首页卡与内容池

首页每张卡包含：

- 缩略图（与详情卡同一张照片，裁成 4:3）
- 名字（具体、有画面）
- 一句话钩子（不是完整理由；完整理由在详情卡里）
- 难度（步行距离的粗分类：近 / 中 / 远，不显示精确距离）
- 一个"换一批"

MVP 的 6 张雾城目的地（用于游戏模式）：

1. **老邮局**：绿漆木门，门口有两个邮筒，其中一个不能用。
2. **钟楼**：整点会慢两分钟，全城的人都按它迟到。
3. **河边面馆**：没有招牌，只卖一种面，下午两点关门。
4. **旧书店**：门口堆的书比店里多，猫睡在收银台上。
5. **修表铺**：开了 27 年，师傅只修机械表。
6. **老茶馆**：竹椅、盖碗茶，下午三点有人掏耳朵。

**选目的地的标准**：具体、公开、有可进入的公共入口、有一点怪、有一个可以讲的特征。不要"某商场""某餐厅"这种没有画面的地方；入口必须现场实测。

**自定义目的地**：v1.0 支持输入地点名，接入 POI 搜索；黑客松用 6 张卡片，避免现场输入和地理编码失败。

### 7.5 旅程模式

旅程模式回答"我想去这个地方"。它不记分，只记录经历。

#### 7.5.1 走法一：模拟（R3）

模拟不是"假地图"，是同一个目的地的沙盘。用户仍然要真的转动手机。

**界面**：

- 屏幕上方：罗盘，指针指向目的地。
- 屏幕下方：只有一个主按钮 **"前进"**，≥ 56px 高，放在拇指能碰到的位置。
- 没有方向键、没有网格、没有地图、没有距离数字。
- 底部辅助：计时、步数、问路、照片、日记。

**罗盘表现（R10 / R11）**：

- **盘面固定不动**：刻度、外壳、北标记、"北"字始终不动。
- **只有指针转**：指针绕着盘心旋转，指向目的地。
- 转动手机时，是"指针相对盘面转动"，不是整个罗盘跟着转。
- 不准把整个盘面旋转来模拟罗盘；用户看一眼就知道"北在哪、目的地在哪边"。
- 指针用形状 + 颜色双重区分（红色箭头 + 三角），不依赖颜色 alone。

**罗盘要主导屏幕（R11）**：

| 项 | 要求 |
|---|---|
| 表盘直径 | 390×844：≥ 330px；430×932：≥ 360px；最大 420px |
| 罗盘区高度 | 行进页 ≥ 50vh，桌面预览可到 60vh |
| 顶部 | 只留一行目的地 + 计时；不放卡片、不放长文案 |
| 底部 | "前进"按钮 ≥ 56px 高，整宽减边距，放在拇指区 |
| 视觉 | 黄铜 + 玻璃质感、清晰刻度、高对比；深色默认；2x/3x 屏不糊 |
| 动效 | 指针 240ms 缓动；只重绘指针，不整盘重绘；60fps |
| 无障碍 | 刻度字 ≥ 14px；罗盘有文字方向兜底；不靠颜色 alone |
| 不裁切 | 390×844 和 430×932 都不裁切、不重叠；安全区留白 |

**视觉验收以 HTML 设计稿为准**：本页只写尺寸和规则；下一轮设计稿必须按项目规则做成可切换明暗的 HTML，并在 390×844 / 430×932 两档截图对照。别用文字描述代替设计稿。

**操作**：

1. 用户水平拿着手机，转动身体或手腕，让手机朝向变化。
2. 罗盘指针跟着手机朝向转；当指针对准目的地（误差 ≤ 10°），罗盘外圈亮起"已对准"。
3. 按一次"前进"，模拟位置沿手机朝向走一步，约 18 米。
4. 走偏了，指针会偏；用户自己转回来，再按前进。
5. 没有"你走错了"的弹窗；阿针会叹气或说"你确定？"。

**首次模拟（必须 60 秒左右完成一次抵达）**：

- 范围约 300 米，最短 4-6 步。
- 起点到目的地是一条清楚的直线，不放 NPC、不放迷雾、不放障碍。
- 目标：新用户从按下"出发"到抵达 ≤ 75 秒；5 个新用户里至少 4 个做到。
- 第一次抵达后，结果页邀请："再走一次完整旅程"，再进入更长距离、有 NPC 的版本。

**没有方向传感器时**：

- 显示"没检测到罗盘：拖动表盘模拟"。
- 用户拖动表盘代替转动手机；仍然只有一个"前进"按钮。
- 不偷偷把"前进"变成"自动走向目的地"；用户必须自己对准。

**验收**：

- 模拟界面没有方向键。
- 只有"前进"一个移动按钮。
- 转动手机时，指针跟着转；不转手机只按前进，会走偏。
- 5 个新用户里至少 4 个在 75 秒内完成第一次抵达。

#### 7.5.2 走法二：真实城市

**流程**：

1. 授权定位和方向传感器（手机里判断朝向的硬件）。
2. 从附近的目的地卡里选一个（不显示精确距离）。
3. 出发，计时开始。
4. 罗盘全屏，指针指向目的地。
5. 底部：计时、"我问了个人"、照片、日记、退出。
6. 距目的地 30 米内，"到了"按钮解锁，用户确认抵达。
7. 旅程小结、日记、分享。

**技术要点**：

- 定位用浏览器 Geolocation API（浏览器提供的定位接口），需要 HTTPS。
- 方向用 DeviceOrientation API（浏览器提供的手机朝向接口）；iOS 需要用户手势触发授权。
- 屏幕常亮用 Screen Wake Lock API（浏览器提供的防锁屏接口）。
- 没有方向权限时，退化为"GPS 移动方向"（走路时根据位置变化推算朝向），并在界面上说明。
- 定位失败时，明确告诉用户去哪打开权限，不假装能工作。
- 目的地坐标做 GCJ-02 → WGS-84 转换；精度 ≤ 50 米、采样 ≤ 15 秒、连续 3 次有效采样，才显示"接近目的地"。
- 过期或漂移的位置不使用；进入范围后由用户点"我到了"，不自动结算。
- 方向不准时提供"罗盘校准"入口，嵌入 `compass-kit/demo.html`，带入当前主题、朝向和目标。

**安全**：

- 默认建议白天；日落后弹一次提醒。
- 目的地必须是公共场所，排除私人住宅、工地、高速、水域。
- "退出"始终可见，退出不扣分、不羞辱。
- 可把实时位置分享给一个紧急联系人。
- 不后台追踪，不上传轨迹，除非用户主动分享。

#### 7.5.3 问路（R4）

- 旅程中，"我问了个人"按钮始终可见。
- 点一下：按钮轻微回弹 + 计数 +1 + 一句轻反馈，不弹窗、不暂停计时。
- 主反馈文案：**"记下了。这条路多了一个人帮你记着。"**
- 计数文案：**"今天第 3 个"**。
- 每次点击在日记时间线加一条：时间 + "问了第 3 个人"。不编造对方长相、性别、年龄；用户没记就不写。
- 问路不加时间惩罚，不设上限（旅程模式）。
- 连续点击 300ms 内只算一次，防止手抖重复计数。
- 抵达后，旅程小结和日记都用这个次数：**"你问了 3 个人。"**

**验收**：

- 点击后 100ms 内有视觉反馈。
- 计数 +1，刷新前不丢。
- 结果页出现问路次数。
- 日记时间线出现对应条数。

#### 7.5.4 抵达

- 指针快速旋转，减速，咔哒锁定。
- 屏幕闪一下暖光。
- 阿针睁大眼："到了。我早说过。"
- 自动进入旅程小结（7.7.1）。

### 7.6 游戏模式

游戏模式回答"我想挑战一局"。它必须有分数，而且有两条得分线。

#### 7.6.1 两条得分线（R5）

- **速度分（0-600）**：按用时和标准时间算。快，分高；慢，分低。
- **相遇分（0-400）**：按问路人数、触发事件、发现地标算。每类有上限，不能刷。
- **总分 = 速度分 + 相遇分，最高 1000。**
- 结果页必须同时显示两条分，不能只显示总分。玩家要能看懂："我可以走快，也可以多聊几个人。"
- 星级：★ 抵达；★ 速度分 ≥ 400；★ 相遇分 ≥ 200。

**公式**：

```text
速度分 = clamp(600 - 3 × max(0, 用时秒 - 标准时间秒), 0, 600)

相遇分 = min(问路人数, 4) × 50
       + min(触发事件数, 2) × 50
       + min(发现地标数, 2) × 50
```

- 问路按"不同的人"算，同一个人重复问不重复计分。
- 事件和地标按"本局第一次触发"算。
- 照片和日记不参与游戏得分；它们属于旅程。
- 标准时间：`最短路径步数 × 6 秒 + 45 秒`。

#### 7.6.2 雾城挑战（MVP 的游戏模式）

**地图**：12×12 网格的虚构小城"雾城"。

- 格子类型：路、建筑、水、地标。
- 河流把城分成两半，只有 2 座桥。
- 建筑不能穿过，必须绕路。
- 起点随机，目的地在 6 个地标里选一个（不能是起点旁边）。
- 迷雾：只能看见当前位置周围 1 格。走过的格子会永久点亮，形成你自己的地图。
- 街道名：横街竖街各有名字，相邻格子会显示路名。
- 地标：靠近时显示图标和一句 flavor 文案。

**操作（棋盘式，和旅程模拟不同）**：

- 四个大按钮（上/下/左/右），44×44 以上。
- 支持滑动和键盘方向键（方便评委用电脑）。
- 每次移动 180ms 动画。
- 罗盘始终在屏幕上方，指针指向目的地。
- 底部：计时、步数、问路、日记。

**为什么两套操作**：游戏模式是"棋盘"，玩家看格子做决策；旅程模拟是"身体"，玩家转手机、按前进。两套操作不要混在一个屏幕里。这是 R8 的一部分。

**罗盘规则**：

- 指针只指目的地，不显示距离。
- **盘面固定，只有指针转**；不要把整个盘面转起来。
- 罗盘是行进页的主视觉：390×844 上表盘直径 ≥ 330px，罗盘区 ≥ 50vh。
- 距目的地 3 格以内，指针开始轻微抖动。
- 进入目的地格子，触发抵达。
- 没有"你走错了"的弹窗。走错就是走错，阿针会叹气，但不会阻止。

**问路**：

- 地图上有 8 个 NPC，分布在不同路口。
- 每个 NPC 只能问一次。
- 点击 NPC，弹出对话卡：头像、名字、一句话指路。
- 指路内容由地图真实路径生成（BFS，广度优先搜索，算出最短路线），再用人物性格包装。
- 部分 NPC 不可靠（30% 概率把东南西北说反一个），玩家不知道是谁。
- 问路不加时间惩罚，但会计入"相遇分"。
- 对话卡底部："记下了"。

**事件与地标**：

- 事件卡最多触发 2 次计分；地标最多 2 个计分。
- 计分只算第一次，避免刷。
- 事件和地标的事实由地图数据决定，AI 只负责语气。

**抵达**：

- 指针快速旋转，减速，咔哒锁定。
- 屏幕闪一下暖光。
- 阿针睁大眼："到了。我早说过。"
- 自动进入游戏得分卡（7.7.2）。

### 7.7 结果页

#### 7.7.1 旅程小结（旅程模式）

旅程结果页的第一优先级是"这段路能不能被讲出来"，不是分数。

**标题**：`到了。`

**阿针**：`我早说过。`

**正文**：`你走了 42 分钟，问了 3 个人，留下 4 张照片和 1 句话。`

**三块内容**：

| 块 | 内容 | 没有数据时 |
|---|---|---|
| 走了多久 | 用时、步数、路线形状（"这条路的形状像一只耳朵"） | 至少显示用时 |
| 遇见谁 | 问路次数；真实城市只写次数，不编对方身份 | "这次没问人。也行。" |
| 留下什么 | 照片数、一句话、日记 | "这次没留照片。下次拍一张。" |

**不出现**：分数、星级、排行榜、用时排名、"最快""超过 XX% 的人"。

**按钮**：`写进日记` / `保存旅程小结图` / `再走一次`。

**路线形状**：抵达后才画，用一条线，不是地图；形状名从固定词库里选，不编故事。

#### 7.7.2 游戏得分卡（游戏模式）

```text
┌─────────────────────┐
│      到了。         │
│   我早说过。        │
│                     │
│  速度分 420         │
│  相遇分 250         │
│  总分   670         │
│                     │
│  ★ ★ ☆              │
│                     │
│ [再玩一局] [挑战朋友]│
└─────────────────────┘
```

- 两条分都要有数字和一句解释：速度分下面写"比标准时间慢 30 秒"；相遇分下面写"问了 4 个人，触发 1 个事件"。
- 标签（"直线天才""城市漫游者"等）只用在游戏模式，不用在旅程模式。
- "写进日记"是次要按钮，不抢"再玩一局"。

### 7.8 日记（R6 / R9）

**原则：先有真实片段，再生成。**

1. 抵达后先问：**"留下一张照片，或者一句话？"** 不直接生成模板。
2. 用户拍照、选照片或写一句后，才生成草稿。
3. 草稿只能使用已经记录的事实：时间、问路次数、照片、用户写的话、目的地。
4. **不得编造用户没做过的事**：没问路就不写问路；没拍照就不写拍照；没去过的地方不写。
5. 没有照片也没有一句话：只生成**旅程卡**（目的地、日期、用时、路线形状），不生成日记正文。
6. 照片：旅程中随时可加；最多 9 张；每张可加一句说明；压缩到最长边 1280px、JPEG 0.7；存在浏览器本地（IndexedDB，浏览器自带的本地数据库），不上传。
7. 时间线：出发 / 问路（每次一条）/ 照片 / 一句话 / 抵达。
8. 成稿：模板生成 3 段，可切换语气（纪实 / 幽默 / 文艺），可编辑。语气只改说法，不改事实。
9. 操作：保存、导出图片、分享。

**入口**：行进中，罗盘底部有一个"日记"把手，向上拉出半屏；向下拉或点罗盘回到旅程。计时不暂停。**它们不是两个页面，是一个页面的两层。**

**照片位**：

- 不强制三个固定位置；用户可以随时加。
- 第一张照片默认当封面，进旅程小结图和分享图。
- 照片可以删除、换封面。
- 没有照片时，不显示空相框墙；显示一句"走到第一个路口，拍一张，或者记一句。"

**空状态**：不写"还没有内容"，写**"走到第一个路口，拍一张，或者记一句。"**

### 7.9 分享（R7）

**主分享物：旅程小结图**

- 尺寸：**1080×1440（3:4，小红书 feed）**；同时可导出 **1080×1920（9:16，微信状态/故事）**。
- 内容：
  - 目的地照片（用户封面或策展照片）
  - 目的地名 + 日期
  - 用时、问路人数、照片数
  - 走过的路线，画成一条线（不是地图）
  - 阿针的一句话
  - 日记里的一行（如果用户写了）
- 邀请语：**"我走到了这里，你会怎么走？"**
- 二维码：右下角 180×180px，编码游戏页 URL，带 `?from=share&mode=journey&d=<destinationId>`。
- 二维码规则：对比度足够、不压在照片细节上、四周留白 ≥ 16px、不缩放变形；390px 宽屏幕上也能扫。
- 分享方式：优先用系统分享（Web Share API）发图片文件；不支持就保存到相册，再发微信/小红书。
- 不做"一键直发微信/小红书"的假承诺；没有官方接口就老老实实保存图片。

**扫码后的落地页**：

- 朋友打开后直接看到：同一目的地的详情卡 + 邀请语 + "开始"按钮。
- 不需要注册，不需要安装。
- 落地页不显示分享者的精确位置、轨迹坐标、照片原图。
- 文案：**"朋友走到了这里。你会怎么走？"** + 目的地名 + `[我也走一遍]`。

**游戏模式的分享：挑战卡**

- 目的地 + 速度分 + 相遇分 + 总分 + 星级。
- 挑战链接把目的地、种子、成绩压进 URL。
- 朋友打开，看到你的得分卡 + "我也走一遍"。
- 二维码同样回游戏页；游戏模式带 `?mode=game&d=<destinationId>&seed=<seed>`。

**隐私**：

- 分享图不含经纬度、轨迹坐标、用户照片以外的隐私信息。
- 二维码只带目的地 ID 和分享来源，不带位置。
- 分享动作必须是用户主动点击；不自动分享。

**应用内广场**：

- MVP：3 张示例卡 + 你自己的卡。
- v1.0：真实用户的时间线，不做算法推荐。

### 7.10 我的冒险

- 本地保存的旅程记录和日记列表。
- 按时间倒序。
- 每张卡显示目的地、日期、用时、缩略图。
- 旅程记录和游戏成绩分开显示，不混在一个列表里。
- 点开可编辑、导出、删除。
- 存储不足时提示导出并清理，不静默丢数据。

### 7.11 设置与安全

- 明暗切换（深色默认）。
- 声音/震动开关。
- 距离显示开关（默认关闭；打开后显示粗粒度"远/近"，仍不显示米数）。
- 安全说明：不闯私人地方、不看手机过马路、天黑前回家。
- 隐私说明：位置只在手机上，不上传。
- 清除本地数据（二次确认）。

## 8. 流程

### 8.1 第一局：旅程模拟（黑客松演示路径）

```
打开链接
  → 首页「旅程」（3 秒看懂）
  → 搜一个已收录地点 / 点一张卡
  → 屏幕下半部目的地卡：照片 + 3 条理由 + 适合时段
  → 出发
  → 怎么走：在这台手机上模拟
  → 转手机 + 按「前进」
  → 60 秒左右第一次抵达
  → 旅程小结：走了多久 / 遇见谁 / 留下什么
  → 留一张照片或一句话（可跳过）
  → 旅程卡 / 日记
  → 分享：旅程小结图 + 二维码
  → 再走一次完整旅程
```

### 8.2 真实城市（v0.9 内测）

```
打开
  → 旅程
  → 搜或选附近目的地
  → 目的地卡（照片 + 理由）
  → 去真实城市
  → 授权定位 + 方向
  → 出发说明 + 安全提示
  → 全屏罗盘
  → 转手机找方向 / 前进
  → 问路 / 拍照 / 记一句
  → 30 米内确认抵达
  → 旅程小结
  → 日记
  → 分享
```

### 8.3 游戏模式

```
打开
  → 首页「游戏」
  → 选一局挑战（雾城 / 会场活动）
  → 规则说明（3 句）
  → 棋盘移动 + 罗盘 + 问路 + 事件
  → 抵达
  → 游戏得分卡：速度分 + 相遇分 + 总分 + 星级
  → 再玩一局 / 挑战朋友
```

### 8.4 朋友扫码进来

```
微信/小红书看到旅程小结图
  → 扫码
  → 落地页：同一目的地 + 「朋友走到了这里。你会怎么走？」
  → [我也走一遍]
  → 目的地卡（照片 + 理由）
  → 出发
```

### 8.5 罗盘与日记的切换

这是用户最常做的动作，必须零学习成本。

- 罗盘是底层画布，永远在。
- 日记是底部抽屉：向上拉 = 打开，向下拉 = 关闭。
- 抽屉打开时，顶部仍能看到罗盘指针的 1/3，计时继续走。
- 抽屉有三个高度：关闭 / 半屏 / 全屏。
- 半屏时可以直接拍照、写一句、看时间线。
- 全屏时进入编辑，罗盘缩成一个小圆点，点击回到半屏。

## 9. 指标

### 9.1 漏斗

| 环节 | 指标 | 目标 |
|---|---|---|
| 打开 → 开始 | 开局率 | ≥ 70% |
| 开始 → 目的地卡 → 出发 | 目的地选择完成率 | ≥ 85% |
| 搜索 → 选中 | 搜索成功率 | ≥ 70% |
| 出发 → 首次抵达（模拟） | 75 秒内抵达率 | ≥ 80% |
| 出发 → 抵达（真实城市） | 抵达率 | ≥ 60% |
| 抵达 → 留下片段 | 照片或一句话添加率 | ≥ 50% |
| 抵达 → 生成分享图 | 分享图生成率 | ≥ 40% |
| 分享 → 扫码打开 | 二维码打开率 | ≥ 15% |
| 7 日 → 二次开局 | 留存 | ≥ 25% |

### 9.2 质量指标

- 旅程模式：平均用时、步数、问路次数、照片数分布；**不看用时排名**。
- 游戏模式：速度分、相遇分、总分的分布；三星率；两条分是否被玩家理解（试玩后问）。
- 目的地卡：打开率、从卡到出发的转化率。
- 搜索：无结果率、无结果后是否选了推荐地点。
- 问路：按钮点击次数、结果页是否显示次数、日记是否记录。
- 日记：编辑率（说明模板不够好）、照片添加率、无片段时是否只出旅程卡。
- 分享：分享图保存率、二维码扫码率。
- 安全事件数（目标 0）。
- 退出率与退出位置。
- 模式检查：旅程结果页出现分数 = 0 次；游戏结果页缺一条分 = 0 次。

### 9.3 黑客松指标

- 5 个陌生试玩者，首次移动时间 < 30 秒。
- 5 个陌生试玩者，至少 4 个在 75 秒内完成第一次模拟抵达。
- 完成一局游戏 < 6 分钟。
- 60% 想再玩。
- 100% 能用一句话描述阿针。
- 0 个"这个按钮是干嘛的"问题。
- 0 个"这是旅程还是游戏"的混淆问题。

## 10. 风险

| 风险 | 可能性 | 影响 | 应对 |
|---|---|---|---|
| 真实行走的安全事故 | 中 | 极高 | 只选公共场所；白天默认；退出始终可见；实时位置共享；夜间提醒；禁止水域/高速/工地目的地 |
| 罗盘不准（磁干扰） | 高 | 中 | 8 字校准引导；GPS 航向兜底；显示"罗盘有点晕"而不是假装准确 |
| 罗盘盘面转动导致读数困惑 | 中 | 中 | 盘面固定不动，只让指针转；盘面刻度始终北朝上，指针指向目的地 |
| 电量消耗 | 高 | 中 | 屏幕常亮按需开启；GPS 1Hz；不做实时地图渲染；低电量模式 |
| 目的地无聊 | 中 | 高 | 人工策展；"有画面"标准；详情卡写具体理由；抵达后评分；差评目的地下线 |
| 目的地照片造假或过时 | 中 | 高 | 只用实拍或授权照片；记录拍摄日期；超过 12 个月更换；不用无关素材冒充 |

## 11. 商业

### 11.1 免费与付费

| 层 | 内容 | 价格 |
|---|---|---|
| 免费 | 旅程不限、每日 1 局游戏挑战、3 个城市目的地、基础日记、基础分享图 | 0 |
| 会员 | 无限局游戏、全部城市包、高级日记模板、分享图皮肤、旅伴皮肤 | ¥12/月 或 ¥68/年 |
| 城市包 | 一个城市的 30-50 个策展目的地 + 主题路线 | ¥12-30 |
| 活动包 | 团建/社群/婚礼：自定义目的地、榜单、专属海报 | ¥299-999/场 |
| 品牌目的地 | 品牌付费成为一周目的地，明确标注"合作目的地" | 按项目报价 |

### 11.2 品牌合作的红线

《纽约客》的故事已经演示了两种结局：律师函，和市场部的"我们其实很喜欢"。犟针的做法：

1. 先拿书面授权，再上线。
2. 合作目的地必须明确标注，不伪装成普通目的地。
3. 品牌不能干预罗盘、不能买"更近的起点"、不能买好评。
4. 每个城市每周最多 1 个合作目的地，避免整座城变成广告。
5. 合作目的地必须通过"值得走"的策展标准，否则不接。

### 11.3 为什么品牌会付钱

- 一个人专门走 40 分钟到店，比一次曝光值钱。
- 旅程小结图是天然 UGC（用户自己生成的内容），带品牌但不硬广。
- 到店动作可核销（v1.1 可加"到店盖章"）。
- 对独立店主、展览、书店、咖啡馆尤其有吸引力。
