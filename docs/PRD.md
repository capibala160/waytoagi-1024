# 犟针 · 产品需求文档（PRD）

> 版本：v0.1（2026-10-24）
> 状态：待 Mike 拍板
> 一句话：输入目的地，罗盘只指方向，不指路。你靠自己的方向感、街上的线索和路人的指路抵达。每一次抵达自动变成一篇可分享的冒险日记。

---

## 1. 定位

### 1.1 这是什么

**犟针**是一款手机网页应用，把"导航"反过来做。

普通导航软件告诉你：往前 200 米右转，再走 3 个路口。它把城市压缩成一条蓝色路线，你不需要看街，不需要记路，也不需要和任何人说话。

犟针只做一件事：**告诉你目的地在哪个方向，然后闭嘴。**

- 没有地图
- 没有路线
- 没有"前方 200 米右转"
- 没有距离数字（默认）
- 只有一个指针，和一座需要你自己读懂的城市

你要到目的地，只能靠三样东西：自己的方向感、街上的招牌和地标、以及问路人。

抵达之后，App 会把你实际走过的路线画出来，配上一张"抵达证明"和一篇自动写好的冒险日记。你可以把它发给朋友，也可以让朋友走同一条路。

### 1.2 为什么做

导航软件优化的是"确定性"：用最少的思考、最短的时间，把你送到。它很高效，但它也把城市变成了传送带。

犟针优化的是"体验"：目的地是确定的，路线是不确定的。它把一次普通出门变成一个小冒险，把"问路"这件有点尴尬的小事变成游戏里的一枚勋章，把"到达"变成一张可以炫耀的证书。

《纽约客》写的那枚只指向时代广场 Olive Garden 的罗盘，5000 人排队订购。它不是一个更好的导航工具，它是一个**故事发生器**。人们买的不是方向，是"我今天有一段可以讲的事"。

### 1.3 产品的一句话

> **目的地是确定的，路线不是。**

### 1.4 名字与角色

| 项 | 内容 |
|---|---|
| 产品名 | **犟针**（jiàng zhēn） |
| 英文名 | Stubborn Needle |
| 标语 | **只指方向，不指路。** |
| 主角 | **阿针**，一枚只认一个方向的铜罗盘 |
| 主角一句话 | 一枚嘴硬心软的铜罗盘，只指方向，不给路线，你绕路它会叹气 |
| 游戏副标题 | 《犟针 · 雾城》 |

"犟"读 jiàng，是认死理、不服劝、不回头的意思，带一点亲昵，不是骂人。"犟针"就是一根劝不动的针，正好是这枚罗盘的性格。

## 2. 用户

### 2.1 核心人群

| 人群 | 画像 | 他们想要什么 | 犟针给什么 |
|---|---|---|---|
| **周末搭子** | 24-33 岁，一二线城市，citywalk 常客，2-4 人小团体 | 一个不用动脑、又不落俗套的周末计划 | 一张目的地卡，一段 1-2 小时的共同冒险 |
| **城市游客** | 25-40 岁，到陌生城市出差或旅行 | 真正认识一座城，而不是打卡 | 用身体记住街道，而不是跟着导航走 |
| **约会中的两个人** | 20-35 岁，想找低成本的共同活动 | 有话可聊，有事可做 | 罗盘制造话题，问路制造共同记忆 |
| **独行者 / 社恐** | 20-35 岁，想出门但不想社交 | 一个安全的出门理由 | 问路按钮把社交变成游戏动作，可做可不做 |
| **社群组织者** | 25-40 岁，组织 10-50 人的城市活动 | 一套现成的城市游戏，有排行榜、有海报 | 活动包：同一目的地、不同起点、统一榜单 |

### 2.2 非目标用户

- 赶时间的人：上班通勤、赶飞机、找医院。这类场景请用高德/百度地图。
- 不愿意走路的人：犟针的乐趣来自步行和观察。
- 需要无障碍导航的视障用户：犟针不是无障碍导航工具，虽然会做基础适配，但不替代专业产品。

### 2.3 用户任务（JTBD，Jobs to be Done，用户想完成的事）

1. **"周末不想再去商场，但也不想做攻略。"**
   → 给我一个具体、有点意思的目的地，别让我选。
2. **"我在这个城市住了五年，但其实只认识公司和家。"**
   → 让我用游客的眼睛重新走一遍。
3. **"我想和这个人多待一会儿，但不知道聊什么。"**
   → 给我们一个共同任务，让对话自然发生。
4. **"我想做点能发出去的东西，但不想摆拍。"**
   → 给我一张有信息量的抵达证明，配一段真的故事。
5. **"我想验证我到底认不认路。"**
   → 给我一个可以重复挑战、有星级和时间的关卡。

## 3. 洞察

### 3.1 从《纽约客》那枚罗盘学到的五件事

1. **约束制造故事。** 一个只能指一个方向的罗盘，比一个什么都能查的手机更好玩，因为它把"找路"变回了问题。
2. **目的地要具体、要有点荒诞。** "时代广场的 Olive Garden"比"附近任意餐厅"好笑得多，也值得走。目的地本身要有故事。
3. **问路是高潮。** 两个人在斯塔滕岛海边，罗盘指向水，他们只能去问长椅上的一对夫妇。那段对话是整篇文章最好的部分。
4. **到达不是终点，复述才是。** 他们走进餐厅，对领位员说"我们跟着罗盘来的"，这才是产品的完成时刻。
5. **法律是产品的一部分。** Olive Garden 的律师函说明：用别人的品牌做目的地，必须先拿授权。这也反过来证明，品牌愿意为"有人专门走过来"付钱。

### 3.2 中国市场信号

| 信号 | 数据 | 对我们的意义 |
|---|---|---|
| citywalk | 小红书话题浏览 21 亿次，搜索同比增长 140 倍，相关笔记 370 万篇；24-33 岁为主力 | 城市漫步已经是大众行为，不需要教育市场 |
| 搭子文化 | 小红书"搭子"内容推动猫鼠游戏第二轮爆发 | 小团体、低门槛、可组队是刚需 |
| 猫鼠游戏 | 单场常达数十至上百人，收费 9.9-29.9 元，小红书相关笔记 26 万篇 | 位置类线下游戏有真实付费意愿，但依赖地图共享 |
| Randonautica | 2020 年夏天约 1080 万用户；随机坐标导致大量"垃圾桶级"目的地 | 纯随机不行，目的地必须被策展 |
| Jet Lag: The Game | 19 季，靠挑战卡、规则变体和重玩性撑住 | 游戏化结构比重内容更耐玩 |
| Polarsteps | 自动记录路线、生成旅行日记、可分享，4.7 分约 37 万评价 | 日记和分享是成熟需求，但它是"记录"，不是"游戏" |

### 3.3 市场空位

现有产品各自只占一角：

- **Locator**：机制最接近，但只是一个网页小玩具，没有游戏循环、没有日记、没有中文内容。
- **As The Crow Flies**：极简罗盘导航，是工具，不是游戏。
- **nomap**：为视障用户做的方向指引，强调震动和箭头，不是冒险。
- **Randonautica**：随机目的地，有病毒传播，但目的地的质量不可控，且出过安全事故。
- **Polarsteps**：旅行日记和分享做得很好，但它是事后记录，不是过程游戏。
- **猫鼠游戏 / 高德群组**：位置社交游戏，规模大，但核心是"追逃"，依赖实时地图。
- **小红书 citywalk 内容**：有路线、有笔记，但没有工具，也没有"只给方向"的约束。

**没有人把"盲罗盘 + 真实城市 + 游戏循环 + 冒险日记 + 社交分享"合在一起。** 这就是犟针的位置。

## 4. 目标

### 4.1 产品目标（v1.0，上线后 3 个月）

| 指标 | 目标 | 说明 |
|---|---|---|
| 开局 → 抵达 | ≥ 60% | 开始走的人里，六成能走到 |
| 抵达 → 生成日记 | ≥ 50% | 一半的人愿意留下记录 |
| 日记 → 分享 | ≥ 40% | 分享是增长引擎 |
| 7 日内二次开局 | ≥ 25% | 证明"想再玩一局" |
| 平均单次用时 | 25-90 分钟 | 太短没故事，太长劝退 |
| 目的地好评率 | ≥ 80% | 解决"垃圾桶问题" |
| 安全事故 | 0 | 不可妥协 |

### 4.2 北极星指标

> **每周完成的冒险数** = 抵达目的地并生成日记的次数。

不是安装量，不是日活。因为犟针的价值不在"打开"，在"走完并留下故事"。

### 4.3 黑客松目标（10 月 25 日 16:00 前）

| 目标 | 验收方式 |
|---|---|
| 评委 5 分钟内独立完成一局 | 找 5 个没看过说明的人试玩，记录首次操作时间 |
| 一局结束后 60% 的人想再来一局 | 试玩后问"还想再玩吗"，记录 |
| 评委能用一句话描述阿针 | 试玩后问"主角是什么性格"，记录 |
| 全部提交物齐备 | 链接、主角卡、演示视频、说明文档 |

## 5. 原则

这六条是产品决策的宪法。功能可以砍，原则不能破。

1. **方向确定，路线不确定。**
   罗盘只回答"在哪边"，不回答"怎么走"。
2. **地图是走出来的，不是给出来的。**
   出发时没有地图。走过后，你走过的路才会变成地图。
3. **绕路是内容，不是错误。**
   不惩罚迷路，不催促进度。迷路指数是一个可以炫耀的标签。
4. **人是最好的导航。**
   问路不是备用方案，是核心玩法。每一次问路都值得被记录。
5. **到达不是终点，故事才是。**
   结果页的第一优先级不是分数，是"这段路能不能被讲出来"。
6. **安全高于惊喜。**
   任何可能让人走进危险、私人区域或夜路的设计，一律砍掉。

### 5.1 七幕

产品的体验由七个瞬间组成。每个瞬间都要被设计，不能靠运气。

| 幕 | 时刻 | 用户感受 | 设计动作 |
|---|---|---|---|
| 1 | 第一眼（0-10 秒） | "这东西有点意思" | 罗盘指针扫入，阿针睁眼，说"往那边。" |
| 2 | 出门（10-40 秒） | "这个目的地有点怪，我想去" | 目的地卡只给名字和一句话，不给距离、不给地图 |
| 3 | 第一次迷路（3-8 分钟） | "我是不是走错了" | 迷雾、建筑挡路、阿针叹气，但不弹"你走错了" |
| 4 | 第一次问路（5-15 分钟） | "原来还能问人" | 一个具体的人、一段具体的话；"人情味 +1" |
| 5 | 抵达（20-60 分钟） | "到了" | 指针旋转、减速、咔哒锁定；阿针说"到了。我早说过。" |
| 6 | 揭晓（到达后 1 分钟） | "原来我走了这么一条路" | 把你走过的路画成一条线，给形状起个名字 |
| 7 | 复述（到达后 5 分钟） | "这个可以发" | 自动日记 + 抵达证明 + 挑战链接 |

七幕里最重要的是第 4 幕和第 5 幕。第 4 幕是人的连接，第 5 幕是奖励。如果只能做好两幕，做这两幕。

### 5.2 反体验

- 不显示距离数字。
- 不弹"你走错了"。
- 不惩罚绕路。
- 不强制注册。
- 不让 AI 替用户抒情。
- 不在抵达前给地图。
- 不把问路做成"失败后的提示"。
- 不用签到、积分、连续登录制造压力。

### 5.3 反目标（即使做出来了也算失败）

- 变成一个"套了罗盘皮肤的地图 App"。
- 用户为了抄近路穿过马路、工地、私人小区。
- 目的地无聊到让人想说"就这？"。
- 日记是千篇一律的 AI 废话，用户不想发。
- 第一局好玩，第二局一样。
- 为了留存，加入签到、积分、强制社交。

### 6.2 P0.5（有余力才做）

- 实战模式：真实 GPS + 手机罗盘 + 6 个会场附近的目的地。
- 事件卡：路上随机遇到 4 个小事件（猫挡路、突然下雨、街头艺人、修路）。
- 道具卡：问路券、旧纸条、半瓶水。
- 实时 AI 铸造与日记（需要服务端代理，避免前端暴露密钥）。

### 6.3 P1（黑客松之后，v1.0）

- 目的地搜索：接入高德/腾讯地图 POI（兴趣点，地图上的地点数据）。
- 盲盒目的地：按半径、类别、营业时间随机。
- 账号与云同步：日记跨设备。
- 应用内广场：真实用户的抵达卡信息流。
- 挑战链接、排行榜、每周盲盒。
- 安全功能：实时位置共享、紧急联系人、夜间提醒、禁区过滤。
- PWA 安装（把网页加到手机桌面，像 App 一样打开）。

### 6.4 P2（更远）

- 原生 App：后台罗盘、震动反馈、锁屏小组件、手表。
- 组队模式：同一目的地、不同起点、团队榜单。
- 城市包：与文旅局、商圈、独立店主合作。
- 品牌目的地：品牌付费成为目的地，但必须明确标注，且不得干预罗盘。
- 线下活动包：团建、社群、婚礼、毕业旅行。

### 6.5 明确不做

- 不做 turn-by-turn 导航。
- 不做实时地图。
- 不做距离数字（至少默认不做）。
- 不做社交 feed 的算法推荐（v1 只做时间线）。
- 不做用户生成目的地的公开市场（先解决审核和安全）。
- 不做广告变现（先做品牌目的地和活动包）。

## 7. 功能

### 7.1 首页

**目标**：3 秒内让人知道这是什么，并开始。

结构从上到下：

1. 品牌区：犟针 logo + "只指方向，不指路。"
2. 主按钮："开始一局"。
3. 一句解释："选一个目的地。罗盘只指方向。剩下的靠你和路人。"
4. **冒险广场**：3-5 张抵达卡（MVP 用示例卡 + 用户自己的卡），每张有目的地、用时、阿针的一句话、"我也去"。
5. 我的冒险：最近 3 篇日记。
6. 底部：安全说明、关于、明暗切换。

**MVP 的"少即是多"**：不做底部 Tab，不做个人主页，不做关注。首页就是"开始 + 看别人的卡 + 看自己的日记"。

### 7.2 旅伴铸造

**目标**：用一句话让主角出现，并让用户觉得"这是我造的"。

流程：

1. 输入一句话，最多 30 字。
2. 三个示例芯片：
   - "一个嘴硬心软的铜罗盘"
   - "见过世面的老怀表"
   - "刚出厂、方向感天才"
3. 点击"铸造"。
4. 1.2 秒装配动画：黄铜零件、齿轮、指针依次落位。
5. 出现角色卡：名字、一句话性格、3 个特质、立绘、口头禅。
6. 操作："换一个" / "就它了"。

**技术兜底**：如果没有可用的 AI 接口，用关键词映射到 6 个预设角色（仍然是 AI 生成的形象），保证 1.2 秒内出结果。有接口时，用服务端代理调用大模型（LLM，能理解和生成文字的大模型），3 秒超时后回退到预设。

**角色卡**要能单独导出为图片，作为黑客松的"主角卡"提交物。

### 7.3 模式选择

| 模式 | 说明 | 默认 |
|---|---|---|
| **演练模式** | 在虚构的"雾城"里走一局。评委、第一次玩的人、社恐都从这里开始 | 是 |
| **实战模式** | 在真实城市里走。需要定位和罗盘权限 | 城市确定后开放 |

演练模式不是"假游戏"，它是产品的**练习场**：先在小城里学会看罗盘、问人、认路，再去真实城市。这个设定同时解决了黑客松"评委不可能走出去"的问题。

### 7.4 目的地卡

每张卡包含：

- 名字（具体、有画面）
- 一句话描述（为什么值得走）
- 一个手绘图标
- 难度（步行距离的粗分类：近 / 中 / 远，不显示精确距离）
- 一个"换一批"

MVP 的 6 张雾城目的地：

1. **老邮局**：绿漆木门，门口有两个邮筒，其中一个不能用。
2. **钟楼**：整点会慢两分钟，全城的人都按它迟到。
3. **河边面馆**：没有招牌，只卖一种面，下午两点关门。
4. **旧书店**：门口堆的书比店里多，猫睡在收银台上。
5. **修表铺**：开了 27 年，师傅只修机械表。
6. **老茶馆**：竹椅、盖碗茶，下午三点有人掏耳朵。

**选目的地的标准**：具体、公开、有可进入的公共入口、有一点怪、有一个可以讲的特征。不要"某商场""某餐厅"这种没有画面的地方；入口必须现场实测。

**自定义目的地**：v1.0 支持输入地点名，接入 POI 搜索（地图上的地点数据）；黑客松用 6 张卡片，避免现场输入和地理编码失败。

### 7.5 演练模式（游戏核心）

**地图**：12×12 网格的虚构小城"雾城"。

- 格子类型：路、建筑、水、地标。
- 河流把城分成两半，只有 2 座桥。
- 建筑不能穿过，必须绕路。
- 起点随机，目的地在 6 个地标里选一个（不能是起点旁边）。
- 迷雾：只能看见当前位置周围 1 格。走过的格子会永久点亮，形成你自己的地图。
- 街道名：横街竖街各有名字，相邻格子会显示路名。
- 地标：靠近时显示图标和一句 flavor 文案。

**操作**：

- 四个大按钮（上/下/左/右），44×44 以上。
- 支持滑动和键盘方向键（方便评委用电脑）。
- 每次移动 180ms 动画。
- 罗盘始终在屏幕上方，指针指向目的地。
- 底部：计时、步数、问路、日记。

**罗盘规则**：

- 指针只指目的地，不显示距离。
- 距目的地 3 格以内，指针开始轻微抖动。
- 进入目的地格子，触发抵达。
- 没有"你走错了"的弹窗。走错就是走错，阿针会叹气，但不会阻止。

**问路**：

- 地图上有 8 个 NPC，分布在不同路口。
- 每个 NPC 只能问一次。
- 点击 NPC，弹出对话卡：头像、名字、一句话指路。
- 指路内容由地图真实路径生成（BFS，广度优先搜索，算出最短路线），再用人物性格包装。
- 部分 NPC 不可靠（30% 概率把东南西北说反一个），玩家不知道是谁。
- 问路不加时间惩罚，但会计入"人情味"。
- 对话卡底部："记下了"。

**抵达**：

- 指针快速旋转，减速，咔哒锁定。
- 屏幕闪一下暖光。
- 阿针睁大眼："到了。我早说过。"
- 自动进入结果页。

**结果页**：

- 用时、步数、问路次数、迷路指数。
- 三星：抵达 / 用时 ≤ 标准时间 × 1.5 / 问路 ≥ 2。
- 一句标签："直线天才""城市漫游者""迷路艺术家""城市诗人"。
- 操作："写进日记" / "再玩一局" / "挑战朋友"。

### 7.6 实战模式

**流程**：

1. 授权定位和方向传感器（手机里判断朝向的硬件）。
2. 从附近的目的地卡里选一个（不显示精确距离）。
3. 出发，计时开始。
4. 罗盘全屏，指针指向目的地。
5. 底部：计时、"我问了个人"、日记、退出。
6. 距目的地 30 米内，"到了"按钮解锁，用户确认抵达。
7. 结果、日记、分享。

**技术要点**：

- 定位用浏览器 Geolocation API（浏览器提供的定位接口），需要 HTTPS。
- 方向用 DeviceOrientation API（浏览器提供的手机朝向接口）；iOS 需要用户手势触发授权。
- 屏幕常亮用 Screen Wake Lock API（浏览器提供的防锁屏接口）。
- 没有方向权限时，退化为"GPS 移动方向"（走路时根据位置变化推算朝向），并在界面上说明。
- 定位失败时，明确告诉用户去哪打开权限，不假装能工作。

**安全**：

- 默认建议白天；日落后弹一次提醒。
- 目的地必须是公共场所，排除私人住宅、工地、高速、水域。
- "退出"始终可见，退出不扣分、不羞辱。
- 可把实时位置分享给一个紧急联系人。
- 不后台追踪，不上传轨迹，除非用户主动分享。

### 7.7 日记

**入口**：行进中，罗盘底部有一个"日记"把手，向上拉出半屏；向下拉或点罗盘回到游戏。计时不暂停。这个设计解决"罗盘和日记之间怎么来回"的问题：**它们不是两个页面，是一个页面的两层。**

**结构**：

1. 头部：目的地、日期、天气、旅伴。
2. 数据：用时、步数、问路、迷路指数。
3. 时间线：
   - 出发（自动）
   - 问路（自动，每次一条）
   - 照片（用户，3 个提示位：出发 / 最迷茫的时候 / 抵达）
   - 一句话（用户）
   - 抵达（自动）
4. 成稿：模板生成 3 段，可切换语气（纪实 / 幽默 / 文艺），可编辑。
5. 操作：保存、导出图片、分享。

**照片**：手机拍照或相册选择，压缩到最长边 1280px、JPEG 0.7，控制存储。MVP 存在浏览器本地（localStorage / IndexedDB，浏览器自带的本地数据库），不上传。

**空状态**：不写"还没有内容"，写"走到第一个路口，记一句"。

### 7.8 分享

**抵达证明海报**（1080×1920）：

- 顶部："抵达证明"印章。
- 目的地名 + 日期。
- 你走过的路线，画成一条线（不是地图，只有线）。
- 数据：用时 / 步数 / 问路 / 迷路指数。
- 阿针的一句话。
- 日记里的一行。
- 底部：犟针 · 只指方向，不指路 + 链接。

**挑战链接**：

- 把目的地、起点、用时、问路次数压进 URL。
- 朋友打开，看到你的卡 + "我也走一遍"。
- 不需要服务器，链接本身就是数据。这是 MVP 在没有后端时的社交闭环。

**应用内广场**：

- MVP：3 张示例卡 + 你自己的卡。
- v1.0：真实用户的时间线，不做算法推荐。
- 分享到微信/小红书：先用系统分享（Web Share API），不行就下载图片。

### 7.9 我的冒险

- 本地保存的日记列表。
- 按时间倒序。
- 每张卡显示目的地、日期、用时、缩略图。
- 点开可编辑、导出、删除。
- 存储不足时提示导出并清理，不静默丢数据。

### 7.10 设置与安全

- 明暗切换（深色默认）。
- 声音/震动开关。
- 距离显示开关（默认关闭；打开后显示粗粒度"远/近"，仍不显示米数）。
- 安全说明：不闯私人地方、不看手机过马路、天黑前回家。
- 隐私说明：位置只在手机上，不上传。
- 清除本地数据（二次确认）。

## 8. 流程

### 8.1 第一局（黑客松演示路径）

```
打开链接
  → 首页（3 秒看懂）
  → 开始一局
  → 一句话铸造旅伴（可跳过，默认阿针）
  → 角色卡（就它了）
  → 演练模式
  → 选目的地（3 选 1）
  → 出发说明（3 行）
  → 雾城游戏（罗盘 + 移动 + 问路 + 日记）
  → 抵达
  → 结果页（星级 + 标签）
  → 写进日记（自动成稿 + 照片位）
  → 生成抵达证明
  → 分享 / 挑战朋友
  → 再玩一局（新目的地）
```

### 8.2 真实城市（v1.0）

```
打开
  → 开始一局
  → 实战模式
  → 授权定位 + 方向
  → 选附近目的地
  → 出发说明 + 安全提示
  → 全屏罗盘
  → 问路 / 拍照 / 记一句
  → 30 米内确认抵达
  → 结果
  → 日记
  → 分享
```

### 8.3 罗盘与日记的切换

这是用户最常做的动作，必须零学习成本。

- 罗盘是底层画布，永远在。
- 日记是底部抽屉：向上拉 = 打开，向下拉 = 关闭。
- 抽屉打开时，顶部仍能看到罗盘指针的 1/3，计时继续走。
- 抽屉有三个高度：关闭 / 半屏 / 全屏。
- 半屏时可以直接拍照、写一句、看时间线。
- 全屏时进入编辑，罗盘缩成一个小圆点，点击回到半屏。

## 9. 指标

### 9.1 漏斗

| 环节 | 指标 | 目标 |
|---|---|---|
| 打开 → 开始 | 开局率 | ≥ 70% |
| 开始 → 出发 | 目的地选择完成率 | ≥ 85% |
| 出发 → 抵达 | 抵达率 | ≥ 60% |
| 抵达 → 日记 | 日记生成率 | ≥ 50% |
| 日记 → 分享 | 分享率 | ≥ 40% |
| 分享 → 新用户打开 | 链接打开率 | ≥ 15% |
| 7 日 → 二次开局 | 留存 | ≥ 25% |

### 9.2 质量指标

- 平均用时、步数、问路次数、迷路指数分布。
- 目的地好评率（抵达后一个表情）。
- "想再玩一局"比例。
- 日记编辑率（说明模板不够好）。
- 分享海报下载率。
- 安全事件数（目标 0）。
- 退出率与退出位置。

### 9.3 黑客松指标

- 5 个陌生试玩者，首次移动时间 < 30 秒。
- 完成一局 < 6 分钟。
- 60% 想再玩。
- 100% 能用一句话描述阿针。
- 0 个"这个按钮是干嘛的"问题。

## 10. 风险

| 风险 | 可能性 | 影响 | 应对 |
|---|---|---|---|
| 真实行走的安全事故 | 中 | 极高 | 只选公共场所；白天默认；退出始终可见；实时位置共享；夜间提醒；禁止水域/高速/工地目的地 |
| 罗盘不准（磁干扰） | 高 | 中 | 8 字校准引导；GPS 航向兜底；显示"罗盘有点晕"而不是假装准确 |
| 电量消耗 | 高 | 中 | 屏幕常亮按需开启；GPS 1Hz；不做实时地图渲染；低电量模式 |
| 目的地无聊 | 中 | 高 | 人工策展；"有画面"标准；抵达后评分；差评目的地下线 |
| 用户作弊（打开高德） | 中 | 低 | 荣誉制；不惩罚；v1.1 考虑"纯净模式" |
| 社恐不敢问路 | 中 | 中 | 问路完全可选；演练模式先练；阿针的台词降低压力 |
| 日记像 AI 废话 | 高 | 高 | 模板只写事实 + 一个具体细节；必须可编辑；三种语气；不堆形容词 |
| 法律与 IP（知识产权） | 中 | 高 | 不用品牌名做目的地；品牌合作必须书面授权；POI 数据用合规接口 |
| 隐私 | 中 | 高 | 位置只在端上；不上传；分享需明确动作；隐私政策 |
| 24 小时做不完 | 高 | 高 | 砍清单提前定；先做演练模式；实战模式可隐藏；不提交半成品按钮 |
| 评委不走路 | 高 | 高 | 演练模式是主提交物；视频演示真实模式 |
| 地图数据合规 | 低（黑客松） | 高（上线） | 上线前接入有资质的地图服务；黑客松用虚构地图 |

## 11. 商业

### 11.1 免费与付费

| 层 | 内容 | 价格 |
|---|---|---|
| 免费 | 每日 1 局演练、3 个城市目的地、基础日记、基础海报 | 0 |
| 会员 | 无限局、全部城市包、高级日记模板、海报皮肤、旅伴皮肤 | ¥12/月 或 ¥68/年 |
| 城市包 | 一个城市的 30-50 个策展目的地 + 主题路线 | ¥12-30 |
| 活动包 | 团建/社群/婚礼：自定义目的地、榜单、专属海报 | ¥299-999/场 |
| 品牌目的地 | 品牌付费成为一周目的地，明确标注"合作目的地" | 按项目报价 |

### 11.2 品牌合作的红线

《纽约客》的故事已经演示了两种结局：律师函，和市场部的"我们其实很喜欢"。犟针的做法：

1. 先拿书面授权，再上线。
2. 合作目的地必须明确标注，不伪装成普通目的地。
3. 品牌不能干预罗盘、不能买"更近的起点"、不能买好评。
4. 每个城市每周最多 1 个合作目的地，避免整座城变成广告。
5. 合作目的地必须通过"值得走"的策展标准，否则不接。

### 11.3 为什么品牌会付钱

- 一个人专门走 40 分钟到店，比一次曝光值钱。
- 抵达证明是天然 UGC（用户自己生成的内容），带品牌但不硬广。
- 到店动作可核销（v1.1 可加"到店盖章"）。
- 对独立店主、展览、书店、咖啡馆尤其有吸引力。
